# Datasheet: `haven-docs-synthetic`

- **Version / date:** v1, 2026-11-07
- **Maintainer:** Haven backend (task P3-04)
- **Location:** generated into `ml/datasets/docs_synthetic/out/` (gitignored) by `ml/datasets/docs_synthetic/generate.py`. Only the generator is committed; the files are rebuilt from `--n` and `--seed`.

## Purpose

An evaluation set for Haven's document extraction (P3-05): reading the EPC rating, council tax band, monthly rent and deposit from renter-supplied documents, and saying "not found" when a value isn't there. `ml/eval/eval_docs.py` reports per-field precision and recall on it.

It must **not** be used as evidence of how well extraction works on real documents. The layouts are generic and simple, and real certificates, tenancy agreements and council letters vary much more. It is also not a template for producing official-looking documents.

## Composition

- **Instance:** one single-page document, rendered twice: a text PDF (`<id>.pdf`, reportlab, Helvetica) and a "scan" image (`<id>.png`, or `<id>.jpg` for the JPEG variant; A4 at 150 dpi, Pillow).
- **Size:** 60 documents by default (`--n`), cycling through 3 document types × 5 image variants, so the default set has 20 of each type and 12 of each variant.
- **Document types:** `epc` (an energy summary with a rating band A–G), `tenancy` (rent per month, deposit, and in about 30% of cases a council tax band), `council_tax` (a notice with a band A–H). Each field is written in one of three phrasings (e.g. "Rent: £950 per calendar month", "The monthly rent is £950.00", "Rent payable: £950 pcm"), so extraction can't rely on a single pattern.
- **Image variants:** `clean`, `rotated` (2–6°), `blurred` (Gaussian, radius 1.2–2.0), `jpeg` (quality 12–25), `low_contrast` (contrast × 0.25). PDFs are always clean text.
- **Labels:** `out/labels.jsonl`, one object per document: `id`, `doc_type`, `variant`, `files` and `fields` with `epc_rating` (A–G or null), `council_tax_band` (A–H or null), `rent_pcm` (integer GBP or null) and `deposit` (integer GBP or null). About 20% of a document's own fields are **deliberately omitted** (the text says e.g. "Rating: see full report"); the label is then `null`, and the correct extractor output is "insufficient evidence".
- **Personal data:** none. Names ("A. Tenant"), landlords ("Example Lettings Ltd") and addresses ("Flat 3, 12 Example Street, Edinburgh") are invented, with no postcodes. Every page starts with "SYNTHETIC - NOT A REAL DOCUMENT".

## Sourcing and consent

- Entirely generated by code; there is no upstream data and nobody's documents were used, so consent doesn't apply.
- Field values are drawn from simple ranges (rent £650–£2,400 in £25 steps, deposit £600–£2,600 in £50 steps). They are not statistics about Edinburgh.
- Images are rendered with a system TrueType font that has a £ glyph (DejaVu Sans, Arial or Liberation Sans, whichever is installed). Without one, "£" is written as "GBP", so images can differ slightly between machines. PDFs are byte-identical for the same `--n`/`--seed` (reportlab invariant mode).

## Licence

Generated by Haven's own code, so no third-party licence applies. No official logos, crests, branding or official templates are used.

## Labelling

Labels are produced by the generator together with the text, so they are exact by construction. There are no annotators, no guideline document and no agreement statistics. The only judgement call is the "omitted" convention: a value that isn't written on the page is `null`.

## Splits

None: the whole set is an evaluation set. Nothing is trained on it, so extraction rules must not be tuned against a fixed seed's output. If rules are developed on it, use a different `--seed` for the final report and record that seed.

## Known biases and limitations

- **Far cleaner than real documents.** One page, one column, no tables, letterheads, stamps, handwriting or multi-page agreements.
- **Phrasing coverage is small** (three variants per field). Real documents word these values in many more ways (e.g. "£950 p.c.m.", rent stated weekly), and an extractor that scores well here may still miss them.
- **EPC documents give only the band** (plus a score in one phrasing), not the full certificate layout with the rating graph.
- **Degradations are synthetic** (uniform blur, rotation, JPEG). Phone photos of paper add perspective, shadows, glare and folds, none of which are modelled.
- **Number formats** are always whole pounds with comma thousands separators.

## Maintenance

- Maintained alongside the extraction code (P3-05). Changing the generator changes the dataset, so bump the version above and note the change below.
- Report problems through the repository's issue tracker. There's no takedown process because the data has no real-world source.
